# Deck v3.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trim and polish the v3.2 conference deck from 120 → 114 slides: live gradients on the cover and closer, terminology fixes (fat→thick, plumbing→glue, socket→bridge), one reframed code slide, a merged wiring slide, a closing insight lead-in, and progressive code-highlight reveals for the two HTTP-transport implementations.

**Architecture:** This is an HTML + Markdown deck. Two synced artifacts must always agree: `presentation/index.html` (each slide is one `<section>` preceded by a `<!-- N · TYPE · title -->` comment marker) and `PRESENTATION_PLAN.md` (each slide is one `### Slide N | TYPE | title` heading). They join by slide number and must stay equal in count and order. All deck-specific styling lives in `presentation/css/deck.css` (NEVER edit `theme.css`/`slide.css` — they are mirrors). We make all content/structure edits anchored by **stable content**, then renumber both files once at the end. iOS-ARCHITECTURE.md is NOT touched (no iOS module/layer story changes). No new assets.

**Tech Stack:** Hand-written HTML5, CSS3 (custom properties from `theme.css`, hand-rolled `tok-*` syntax tints, CSS `@keyframes`), no build step, no JS changes. Verification is via `grep` sanity checks + serving the deck locally and clicking through.

**Spec:** `docs/superpowers/specs/2026-05-27-deck-v3.3-design.md`
