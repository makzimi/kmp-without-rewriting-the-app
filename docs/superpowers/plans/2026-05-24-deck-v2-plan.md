# Deck v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement v2 of the "KMP without rewriting the app" deck per spec `docs/superpowers/specs/2026-05-24-deck-v2-design.md` — compact BIG-WORD chains, rewrite slide 34, restructure Part 5/6 around combo-as-pilot, wire 13 user-provided assets, refresh code-path captions for the KMP module split, sync all docs.

**Architecture:** Static HTML/CSS/JS deck. No build step, no test framework. "Tests" are (a) the sanity-check shell commands from `CLAUDE.md` (slide count / comment marker gap detection / plan-deck sync) and (b) visual walkthrough in a browser. Each task ends with a verification step and a commit. Commits accrue throughout — the final task tags `v2`.

**Tech Stack:** HTML5, CSS3 (custom properties + a custom `tok-*` syntax-tint scheme), vanilla JS (`presentation/js/nav.js`), inline SVG, `<video>` with VP9. No external runtime deps.

**v1 tag:** Already created at `9a34d00` (the Initial commit). Confirmed in task 1.

**Critical rules (from `CLAUDE.md`):**
- Every slide change touches **both** `PRESENTATION_PLAN.md` AND `presentation/index.html`. Mirrored via comment markers `<!-- N · TYPE · title -->` and plan headings `### Slide N | TYPE | title`.
- v2 adds a third synced artifact: `iOS-ARCHITECTURE.md`. Only relevant when the talk's iOS-architecture story changes — for v2 it doesn't, so the doc only gets a one-line preamble.
- Theme CSS files (`presentation/css/theme.css` and `presentation/css/slide.css`) are **mirrors** of `dodo-theme/css/`. Don't edit them. All deck-specific CSS goes in `presentation/css/deck.css`.
- Never hardcode hex codes or font names — use CSS variables from `theme.css`.

## Conventions used in this plan

- **Slide numbers in task names** refer to current (v1) numbering until task 24, where a single renumber pass corrects everything.
- **"Find" steps** use `grep -n` so a sub-agent without prior context can locate the slide.
- **Code blocks marked HTML/MD/CSS** are the exact text to insert / replace.
- **Plan and deck edits in the same task** — never split them across tasks; the golden rule is they must stay in sync.
- **Every task ends with a commit.** Per-task commits are kept; the final task tags `v2`.

### Task 3: Re-encode `microinteraction.webm` to ≤ 12 MB

**Files:**

- [ ] **Step 2: Record the original size**

Run:
```bash
ls -lh presentation/assets/media/microinteraction.webm | awk '{print $5}'
```
Expected: ~49 MB.

- [ ] **Step 3: Two-pass VP9 re-encode at 1.5 Mbit/s**

Run:
```bash
cd presentation/assets/media
ffmpeg -y -i microinteraction.webm -c:v libvpx-vp9 -b:v 1500k -pass 1 -an -f null /dev/null
ffmpeg -y -i microinteraction.webm -c:v libvpx-vp9 -b:v 1500k -pass 2 -an microinteraction.compressed.webm
```
Expected: completes without error in ~1-3 min.

- [ ] **Step 4: Verify the compressed file is ≤ 12 MB**

Run:
```bash
ls -lh microinteraction.compressed.webm | awk '{print $5}'
```
Expected: under 12 MB. If 12-15 MB, accept. If still > 15 MB, drop bitrate to `-b:v 1000k` and re-run step 3.

- [ ] **Step 5: Visually verify the compressed result by playing it**

Run:
```bash
open microinteraction.compressed.webm
```
Expected: video plays; visible quality is comparable to the original at slide-render size (~240×480 px display). If quality is bad, re-encode at `-b:v 2000k` instead.

- [ ] **Step 6: Replace the original with the compressed version**

Run:
