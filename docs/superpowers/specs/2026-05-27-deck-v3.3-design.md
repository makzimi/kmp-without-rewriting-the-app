## 1. Two reusable CSS mechanisms

Both live in `presentation/css/deck.css` (the deck-specific stylesheet — NOT the
`theme.css`/`slide.css` mirrors). Build these first; the slide edits depend on
them.

### 1.1 `.bg-gradient-live` — animated cover gradient

Today `.slide--cover` paints two static radial gradients (peach top-right,
purple bottom-left) over `--color-bg`. v3.3 makes that pair **slowly drift and
scale** so the slide feels alive without distracting.

- New class `.bg-gradient-live` carrying the two radial gradients + a slow
  animation. Drives `background-position` and `background-size` (radial
  `background-image` itself can't tween, but position/size can) so each bloom
  gently moves and breathes.
- `@keyframes gradient-drift`: ~18–24s, `ease-in-out`, `infinite alternate`.
  Movement amplitude small (a few percent of the canvas) and scale range subtle
  (e.g. 100%→115%) — "barely-there life", not a lava lamp.
- Gated by `@media (prefers-reduced-motion: reduce)` → animation `none`,
  gradients render static (identical to today's cover).
- Colors via existing theme variables (`--color-pastel-peach`,
  `--color-pastel-purple`, `--color-bg`). No raw hex.

Application:
- **Slide 1 (cover):** the live class supplies the gradients. The static
  gradient currently on `.slide--cover` in `deck.css` is removed/superseded so
  there is one source of truth for the cover background.
- **Last slide (v3.2 #120, "Thank you. Questions?"):** currently a plain white
  `slide--content`. Add `.bg-gradient-live` to its `<section>` so the closer
  bookends the opener. The dark contact text stays readable — the pastels fade
  to white/transparent and the gradients sit behind the content.

### 1.2 `.code-dim` + `.hl-keep` — progressive code highlight

Powers the new transport-reveal slides (§3.4). Pure CSS, no JS.

- `pre.code-block.code-dim` → every `tok-*` token inside flattens to a light
  grey at a lighter weight (the whole snippet "recedes").
- Any region wrapped in `<span class="hl-keep">…</span>` **restores full token
  colors and renders bolder**, so it pops forward against the grey.
- Implemented by overriding `.code-dim .tok-*` to grey, then re-asserting real
  colors under `.code-dim .hl-keep .tok-*` (+ `font-weight` bump on
  `.hl-keep`).
- Reuses the existing `tok-*` palette; grey via an existing muted text variable.

This is the "highlight = keep color, even bolder; rest = light grey" behavior
requested. Each reveal step is its own slide (one slide = one event — the deck
has no per-slide step JS), reusing the base slide's exact code markup with
`code-dim` added to the `<pre>` and the relevant lines wrapped in `.hl-keep`.

### 1.3 `hl-fix` — "KMP fixes this" highlight (slide 57)

A sibling of the existing `hl-bug` class (orange, "divergence bug") but tinted
**purple** (`--color-accent-purple`) to read as "this is the thing KMP
eliminates" rather than "danger". Used only on slide 57 (§2, row 57).

## 5. Sync obligations (the §0 rule)

For every change:

- Update **`presentation/index.html`** (`<section>` + `<!-- N · TYPE · title -->`
  comment marker).
- Update **`PRESENTATION_PLAN.md`** (`### Slide N | TYPE | title` heading,
  body, and the **Slide-count summary** table + pacing note).
- **Renumber once, last:** after all add/remove/merge edits, renumber comment
  markers 1..114 and plan headings 1..114 so they match in DOM/file order. Then
  run the §0 sanity checks (slide count equal in both files; markers 1..N no
  gaps/dupes).
- Update the informational counter near the bottom of `index.html`
  (`<span id="tot">127</span>` is currently stale — set it to 114; `nav.js`
  computes the real total at runtime regardless).
- **iOS-ARCHITECTURE.md:** unchanged (confirm no edit touched the iOS
  module/layer story or its code).
- **ASSETS.md:** scan for stale slide-number references; the only asset use is
  the existing `drinkit-lab-1.png` on slide 70 (no new asset). Touch up any
  slide-number citations that shifted.
